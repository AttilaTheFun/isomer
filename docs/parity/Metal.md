# Metal

Isomer's Metal is Apple's classic Metal API, written in Swift: devices, command queues and command buffers; render, compute and blit command encoders; buffers, textures and texture views, samplers, depth-stencil states; libraries made from Metal Shading Language source, their functions, and render and compute pipelines. Shaders are translated from MSL to WGSL by IsomerMetal's translator (in Swift, at `makeLibrary(source:options:)`); what a device records is handed to a backend as one command stream per command buffer, which runs it on WebGPU in a browser. Metal 4, ray tracing, machine learning and the features of Apple's GPUs that WebGPU does not have are left out. On Apple platforms an app uses Apple's Metal.

## Implemented differently

- The protocols are Swift protocols over `AnyObject` (Apple's are Objective-C protocols over `NSObjectProtocol`), and the descriptors are Swift classes; `copy()` is there for the descriptors apps copy.
- A library is made from source only: there is no compiled default library (`makeDefaultLibrary()` returns nil) until a build rule embeds an app's `.metal` sources. The shader subset the translator reads, and what it reports as unsupported, is in `metal/isomer_metal/translator` (its errors name the line).
- `waitUntilCompleted()` and `waitUntilScheduled()` return at once in a browser, where the GPU's work finishes on the page's event loop that a blocked call would hold. Completed handlers run when the work is done, after what it wrote has come back.
- Memory the CPU sees: a buffer that is not `.storageModePrivate` sends its bytes to the GPU with every command buffer that uses it once `contents()` has been asked for, and what the GPU writes to it (a writable shader buffer, a blit's destination) comes back before the command buffer's completed handlers run. A texture's GPU contents come back after a blit encoder's `synchronize(resource:)` (macOS's rule for managed textures), not by themselves.
- The level-of-detail clamps given with `setFragmentSamplerState(_:lodMinClamp:lodMaxClamp:index:)` and the like are not applied (a WebGPU sampler's clamps are fixed when it is made: MTLSamplerDescriptor's). WebGPU has one viewport and one scissor rectangle: `setViewports` and `setScissorRects` use the first.
- WebGPU's limits apply: a buffer bound to a shader starts at a multiple of 256 bytes, a vertex function writes no buffer, threadgroup memory is declared in the kernel, `.lines` triangle fill and `.clamp` depth clip are not done, and multisampling is 1 or 4 samples.
- Pixel formats are the ones WebGPU has (no compressed, packed 16-bit, YUV or extended-range formats); `.a8Unorm` and the sRGB single- and two-channel formats are missing.
