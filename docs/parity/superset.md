# Where Isomer is a superset of Apple's interfaces

The other half of [missing/](missing/), which lists what Isomer lacks. An app written against Isomer's Apple-named modules should build with Apple's; this page lists what could keep one from doing so, and what Isomer adds beside them. Generated by `tools/parity/parity.py` on 2026-10-19 from Apple's iOS 27.0 SDK and Isomer at `8fa42f41`.

## What `--check --strict` keeps out (the wasm build)

Each Apple-named module as wasm builds it: declarations Apple's (iOS's or macOS's) lacks (SPI and underscored names included), declarations Apple has with other parameter or result types, and conformances Apple's same type lacks (Sendable and the other marker protocols aside, below). `tools/parity/parity.py --check --strict` fails on any of them except in a module marked as a known gap.

### ImageIO: not a subset yet

Isomer's ImageIO came before the strict-subset rule and is not a subset yet, so `--check` reports it without failing. What is not Apple's: (1) it declares `CGImage` (with `width` and `height` as stored `Int` properties), which on Apple is CoreGraphics' class, not ImageIO's; (2) `CFData`, `CFString`, `CFDictionary` and `CFTypeRef` are typealiases of `Data`, `String`, `[String: Any]` and `Any`, where Apple's are CoreFoundation's classes (so `CGImageSourceCreateWithData(_:_:)` and its siblings take other types than Apple's); (3) the host's hooks are public: `_ImageIOHost` (decode, release), `CGImage._source` and `CGImage._pendingBytes`. The fix: `CGImage` into Isomer's CoreGraphics, the CF names Apple's (or the functions' parameters spelled as Apple's interface spells them, `CFData` as a class of Isomer's CoreFoundation-shaped types), and the hooks `package` (as the SwiftUI runtime's plumbing is).

Declarations Apple's lacks: `_ImageIOHost` (shared/image_io/ImageIO.swift:50), `_pendingBytes` (shared/image_io/ImageIO.swift:35), `_source` (shared/image_io/ImageIO.swift:32).

## Behaviour that differs

Declarations Isomer has, behaving otherwise than Apple's (from tools/parity/reasons):

- **CoreGraphics**: `CGFloat` is a `Double` on every architecture, as Apple's is on every platform Apple ships (swift-corelibs-foundation makes it a `Float` on 32-bit architectures, wasm32 among them): a layout computed in WebAssembly is the one computed natively. On 32-bit architectures its bit-level API (`bitPattern`, `RawSignificand`, `significandBitPattern`) is therefore 64 bits wide (`UInt64`) rather than `UInt`.
- **CoreGraphics**: `CGColor` keeps the components it was made with: there is no color management, and a device RGB color is drawn as sRGB.
- **CoreGraphics**: `CGPath` stores what CoreGraphics stores (moves, lines, quadratic and cubic curves, closes); arcs, ellipses and rounded rectangles become cubic curves as CoreGraphics makes them. `contains(_:using:transform:)` flattens curves into 16 or 24 segments.
- **CoreGraphics**: `CGPathElement.points` comes from `applyWithBlock` only: the C-function form, `apply(info:function:)`, would need a C function pointer over a Swift type.
- **Foundation**: `Bundle`, `InputStream` and `OutputStream` are Swift classes, not `NSObject` subclasses. A bundle is a directory found on the file system (`ISOMER_BUNDLE_PATH`, else the executable's directory); it reads no Info.plist and no strings tables (`localizedString` returns the value or the key), and `Bundle(for:)` is the main bundle. Streams read and write memory and files synchronously, with no run loop or delegate events.
- **Foundation**: Without `--@isomer//foundation:internationalization`, `Calendar`'s symbol lists (`shortWeekdaySymbols`, `monthSymbols`, `amSymbol`…) are English whatever the calendar's locale; with it they are ICU's.
- **Foundation**: The "localized" string comparisons (`localizedCompare`, `localizedStandardCompare`, `localizedCaseInsensitiveContains`…) compare without locale data. `String(format:)` does not apply a locale.
- **Foundation**: `CharacterSet` equality between sets that are not explicit ranges compares every code point (slow, rare), and its hash reads only the ASCII and Latin-1 range.
- **Foundation**: Formatting and parsing, locales, calendars beyond the Gregorian and time zones beyond GMT (FoundationInternationalization, over ICU) are an app's choice: counted here as present, they are there when the app builds with `--@isomer//foundation:internationalization`. ICU's data then comes with the app; `isomer_web_app(icu_locales = ["en", …])` keeps only the languages it names (34 MB of data becomes 6 to 7 MB for one to five languages).
- **Foundation**: What corelibs adds to swift-foundation and apps reach for, written in Swift over swift-foundation and the C library: `NSRange` and its functions, `NSLock`, `NSRecursiveLock`, `NSCondition`, `Thread` (pthreads; in WebAssembly without threads there is one thread and starting another stops the program), `FileHandle` (reading, writing, seeking; not the run-loop background reads), `NSNumber` (not bridged: `intValue`, not `as? Int`), `NSRegularExpression` and `NSTextCheckingResult` (over Swift's `Regex`, matching by Unicode scalar with UTF-16 ranges; patterns in the syntax both read), `NSTemporaryDirectory()` and `NSHomeDirectory()`. They are Swift classes, not NSObject subclasses; `Thread.threadDictionary` is a Swift dictionary.
- **Foundation**: `URLSession` sends http and https requests through the HTTP transport the platform's host installs in IsomerFoundation (`IsomerNetwork.http`: the browser's `fetch`, Android's HTTP stack, Apple's URLSession under WAMR) and opens WebSockets through its WebSocket transport; without one a task fails with `URLError.notConnectedToInternet`. `file:` and `data:` URLs are read without a transport. A body is sent and received whole; the host's stack keeps its own cookies and cache and follows redirects. Completion handlers run on a task of their own, not on a delegate queue. `suspend()` keeps a task that has not started from starting; one already loading goes on. Configuration and request properties that steer Apple's network stack (cellular, expensive and constrained access, service types, connections per host, waiting for connectivity) are kept and not acted on. `URLSessionWebSocketTask.sendPing` answers once the connection is open (the transports carry no pings), and a close code `CloseCode` has no case for (an application's 4000s) reads as `.invalid`, where Apple's enum, imported from C, holds the number. `URLRequest.CachePolicy`, `NetworkServiceType` and `Attribution` are enums of `URLRequest`'s own (Apple's are typealiases of `NSURLRequest`'s); `URLResponse`, `URLSession` and its tasks and configuration are Swift classes. `Error.localizedDescription`, URLError's descriptions and `HTTPURLResponse.localizedString(forStatusCode:)` are English.
- **SwiftUI**: Behavior the renderers cannot yet give is accepted and ignored or approximated (docs/swiftui_api_audit.md, section 5): `.transition` is accepted but not animated, springs are ease-outs, `GeometryProxy.frame(in:)` is relative to the view.
- **Metal**: The protocols are Swift protocols over `AnyObject` (Apple's are Objective-C protocols over `NSObjectProtocol`), and the descriptors are Swift classes; `copy()` is there for the descriptors apps copy.
- **Metal**: A library is made from source only: there is no compiled default library (`makeDefaultLibrary()` returns nil) until a build rule embeds an app's `.metal` sources. The shader subset the translator reads, and what it reports as unsupported, is in `metal/isomer_metal/translator` (its errors name the line).
- **Metal**: `waitUntilCompleted()` and `waitUntilScheduled()` return at once in a browser, where the GPU's work finishes on the page's event loop that a blocked call would hold. Completed handlers run when the work is done, after what it wrote has come back.
- **Metal**: Memory the CPU sees: a buffer that is not `.storageModePrivate` sends its bytes to the GPU with every command buffer that uses it once `contents()` has been asked for, and what the GPU writes to it (a writable shader buffer, a blit's destination) comes back before the command buffer's completed handlers run. A texture's GPU contents come back after a blit encoder's `synchronize(resource:)` (macOS's rule for managed textures), not by themselves.
- **Metal**: The level-of-detail clamps given with `setFragmentSamplerState(_:lodMinClamp:lodMaxClamp:index:)` and the like are not applied (a WebGPU sampler's clamps are fixed when it is made: MTLSamplerDescriptor's). WebGPU has one viewport and one scissor rectangle: `setViewports` and `setScissorRects` use the first.
- **Metal**: WebGPU's limits apply: a buffer bound to a shader starts at a multiple of 256 bytes, a vertex function writes no buffer, threadgroup memory is declared in the kernel, `.lines` triangle fill and `.clamp` depth clip are not done, and multisampling is 1 or 4 samples.
- **Metal**: Pixel formats are the ones WebGPU has (no compressed, packed 16-bit, YUV or extended-range formats); `.a8Unorm` and the sRGB single- and two-channel formats are missing.
- **CoreTransferable**: `Transferable` has no requirements here: the hosts hand over files, and `PhotosPickerItem.loadTransferable(type:)` and `.dropDestination(for:)` read them as `Data` or `URL`. A type of an app's own (with its `transferRepresentation`) is not loaded through it yet.
- **UniformTypeIdentifiers**: A type is its identifier and MIME type: there is no type registry or conformance tree, so `UTType(_:)` knows the common identifiers and `UTType(mimeType:)` / `UTType(filenameExtension:)` the common MIME types and extensions, and other identifiers are dynamic types with no MIME type.
- **PhotosUI**: A picked item's identifier is the picked file's path (its name, through `itemIdentifier`), not a photo library asset's: there is no photo library.
- **PhotosUI**: `selectionBehavior` and `preferredItemEncoding` are taken and left to the host's picker.
