# Metal: what Isomer does not have yet

Every declaration of Apple's Metal interface (iOS 27.0 SDK) that Isomer's Metal lacks, with Apple's signature: the list to choose what to implement next from. [Metal.md](../Metal.md) has the counts, the reasons and what is implemented differently. Generated by `tools/parity/parity.py` on 2026-10-19 with Isomer at `8fa42f41`.

Areas are ordered planned, then maybe, then the rest, larger first; within an area, types with the most missing first. "The type too" marks a type Isomer does not declare at all; elsewhere the type is there and these members are not. A version is the iOS release that introduced the declaration.

## Precompiled libraries (4)

Why: Libraries from a bundle, a URL or compiled data. The plan is a build rule that embeds an app's `.metal` sources, translated at build time, as its default library.

Intent: planned.

- `func makeLibrary(data: dispatch_data_t) throws -> any MTLLibrary` (iOS 8)

## Metal 4 (590)

Why: Metal 4's command allocators, argument tables, compilers and pipeline descriptors (iOS 26). The classic API comes first; Metal 4's explicit model maps to WebGPU about as well, and is a candidate once apps use it.

Intent: maybe.
