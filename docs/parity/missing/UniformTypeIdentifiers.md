# UniformTypeIdentifiers: what Isomer does not have yet

Every declaration of Apple's UniformTypeIdentifiers interface (iOS 27.0 SDK) that Isomer's UniformTypeIdentifiers lacks, with Apple's signature: the list to choose what to implement next from. [UniformTypeIdentifiers.md](../UniformTypeIdentifiers.md) has the counts, the reasons and what is implemented differently. Generated by `tools/parity/parity.py` on 2026-10-23 with Isomer at `0a142780`.

Areas are ordered planned, then maybe, then the rest, larger first; within an area, types with the most missing first. "The type too" marks a type Isomer does not declare at all; elsewhere the type is there and these members are not. A version is the iOS release that introduced the declaration.

## Conformances Isomer's types lack (4)

Types both have, conforming on Apple to protocols Isomer's do not (Sendable is below): code that compares, hashes, encodes, prints or uses one so builds with Apple's only.

- `UTType`: `CustomDebugStringConvertible`, `CustomStringConvertible`, `Decodable`, `Encodable`

## Objective-C conformances (not planned) (1)

What Apple's types conform to as Objective-C classes or for bridging to them (NSObjectProtocol, NSCopying, NSCoding, CVarArg, ReferenceConvertible…). Isomer's Foundation has no Objective-C classes (2026-10-12: no Objective-C APIs).

- `UTType`: `ReferenceConvertible`
