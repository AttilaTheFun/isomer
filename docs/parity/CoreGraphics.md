# CoreGraphics

Isomer's CoreGraphics is the part of Apple's CoreGraphics that Swift code, SwiftUI's interface above all, reaches for: `CGFloat` and the geometry types with their C-style functions, `CGAffineTransform`, `CGColor` and `CGColorSpace`, `CGPath` and `CGMutablePath`, line caps and joins, blend modes. It is written in Swift; CoreGraphics' C API that rests on CoreFoundation or callbacks into C is left out. On Apple platforms an app uses Apple's CoreGraphics.

## Implemented differently

- `CGFloat` is a `Double` on every architecture, as Apple's is on every platform Apple ships (swift-corelibs-foundation makes it a `Float` on 32-bit architectures, wasm32 among them): a layout computed in WebAssembly is the one computed natively. On 32-bit architectures its bit-level API (`bitPattern`, `RawSignificand`, `significandBitPattern`) is therefore 64 bits wide (`UInt64`) rather than `UInt`.
- `CGColor` keeps the components it was made with: there is no color management, and a device RGB color is drawn as sRGB.
- `CGPath` stores what CoreGraphics stores (moves, lines, quadratic and cubic curves, closes); arcs, ellipses and rounded rectangles become cubic curves as CoreGraphics makes them. `contains(_:using:transform:)` flattens curves into 16 or 24 segments.
- `CGPathElement.points` comes from `applyWithBlock` only: the C-function form, `apply(info:function:)`, would need a C function pointer over a Swift type.
