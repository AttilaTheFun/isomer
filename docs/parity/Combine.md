# Combine

Isomer's Combine is its own implementation of Apple's interface, written from Apple's .swiftinterface (OpenCombine read for behaviour, nothing taken from it): publishers, subscribers and subjects, every operator, schedulers, `AsyncPublisher`, and `ObservableObject` with `@Published`, so code written for SwiftUI before Observation builds unchanged. It depends on the standard library and the C library's mutexes alone and sits beneath Isomer's Foundation, which imports it as Apple's does (the run loop's, Dispatch's and an operation queue's schedulers, and its coders' `TopLevelEncoder` and `TopLevelDecoder` conformances, are Foundation's side, as on Apple platforms). On Apple platforms an app uses Apple's Combine.

## Implemented differently

- `ObservableObject`'s default `objectWillChange` finds the object's `@Published` properties with `Mirror` (its superclasses' too) and keeps the publisher in their storage, made at the first read; a set through the property, or through `assign(to: &$property)`, sends it before the value changes. An object with no `@Published` property has nowhere to keep one and gets a new publisher at each read, which nothing sends (declare `objectWillChange` to send it yourself, as with Apple's).
- `combineLatest` asks its publishers for everything and keeps only the latest tuple while downstream asks for none; `zip` passes downstream's demand to each publisher. `merge` and `flatMap` with limited demand ask each publisher for one value at a time.
- `breakpoint` and `breakpointOnError` raise SIGTRAP where the C library has signals (Android, Linux); a WebAssembly guest has none, so there they stop the program.
- Subscriptions' and subscribers' descriptions and mirrors give names only, and `print`'s lines have Apple's form (`prefix: receive value: (1)`) without promising every word of it. `Subscribers.Demand` is coded as one unsigned number; `Subscribers.Completion` (`success`, `error`) and `Record` (`recording`, `output`, `completion`) are coded with the keys Apple's use.
- State is kept under pthread mutexes (Windows: critical sections), released before any call out to a subscriber or a closure; the operators that call one subscriber from several sources (merge, combineLatest, zip, flatMap) and the subjects hold a recursive lock around those calls, so they arrive one at a time. In WebAssembly without threads the locks only count.
